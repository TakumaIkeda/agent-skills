# ドメイン設計（実装前フェーズ）

このフェーズの成果物は「コンパイルが通る型定義と関数シグネチャ」だけ。関数本体は書かない（すべて `todo!()`）。

## 0. 適用判断

次のどれにも当てはまらなければ、このスキルは使わずにその旨を報告して終了する。

- 状態遷移がある（例: 下書き → 確定 → キャンセル）
- 生成時に守るべき業務ルール（不変条件）を持つ値がある
- 複数の検証・判断を経て結果が決まる処理がある

## 1. 手順

1. **ワークフローを列挙する**
   各ワークフローについて、名前・きっかけとなるコマンド・入力・成功時の出力（ドメインイベント）・失敗の種類を表にする。
2. **入力の境界を引く**
   外から来る未検証の入力（プリミティブ型の構造体）と、検証済みのドメイン型を別の型にする。
3. **値オブジェクトを定義する**（ルールは §2.1）
4. **状態を定義する**（ルールは §2.2）
5. **ワークフローのシグネチャを書く**（ルールは §2.3）
6. **I/Oの置き場所を決める**（ルールは §2.4）
7. **エラー型を定義する**（ルールは §2.5）
8. **スタブを書き、`cargo check` を通す**

## 2. 型設計ルール

### 2.1 値オブジェクト

- newtype で包み、フィールドは private にする。
- 生成は `TryFrom` または `fn new(...) -> Result<Self, E>` のみ。生成後は不変条件が常に成り立つこと。
- 中身の取り出しは参照を返すメソッドにする。`pub` フィールドや setter は作らない。

### 2.2 状態

- **永続化をまたぐ状態**（DBから読んだ時点では分からない状態）は `enum` で表す。リポジトリはこの `enum` を返す。
- **1つのワークフロー内の段階**は別々の型にする（例: `UnvalidatedOrder` → `ValidatedOrder` → `PricedOrder`）。
- 状態遷移は `self` を消費する関数にする。
  `fn confirm(self, ...) -> Result<ConfirmedOrder, ConfirmError>`
- `Option` を状態の代わりに使わない（「`confirmed_at` が `Some` なら確定済み」は禁止）。
- `PhantomData` を使ったジェネリックな typestate は原則使わない。

### 2.3 ワークフロー

- ワークフローは純粋な同期関数にする。`async` も I/O も禁止。
- 現在時刻・ID生成・乱数・DBから読んだ値は、すべて引数で受け取る。
- 戻り値はドメインイベント、または遷移後の状態にする。
  `fn place_order(order: ValidatedOrder, prices: &PriceTable, now: OffsetDateTime) -> Result<Vec<OrderEvent>, PlaceOrderError>`

### 2.4 I/O（依存）

- I/O はユースケース層（ワークフローの外側）で先に実行し、結果を値としてワークフローに渡す。
- ワークフローの途中の結果によって必要な I/O が変わる場合に限り、trait を定義して受け取る。
- `Box<dyn Fn>` やクロージャで依存を渡さない。

### 2.5 エラー

- `thiserror` で、ワークフローごとにエラー `enum` を定義する。
- `anyhow` はドメイン層・ユースケース層で使わない。
- 全項目のエラーを返す必要がある入力検証は、`?` で止めずに `Vec<ValidationError>` に溜める。

### 2.6 禁止事項

- `.clone()` による状態更新（`..self.clone()` など）
- ドメイン層での `unwrap` / `expect`
- ドメイン層の `serde` 依存 <!-- TODO: チームの方針に合わせて変更 -->

## 3. 出力

1. ドメインモジュールへの型定義とシグネチャ（本体は `todo!()`）
2. 短い設計メモ
   - ワークフロー一覧表（§1-1 の表）
   - 状態遷移（Mermaid の stateDiagram）
   - 判断に迷った点と、選ばなかった案

## 4. 完了条件と引き継ぎ

- `cargo check` が通ること。
- 型とメモをユーザーに提示し、承認を待つ。**承認前に実装を始めない。**
- 実装フェーズでシグネチャの変更が必要になったら、勝手に変えずに止まって理由を報告する。
